# 园区问卷 · V6「清简」可交互原型

这是整站 UI/UX 重设计的**可交互 HTML 原型**：不是截图拼贴，也不是展示页。
问卷能答、校验会拦、结果会算、列表能搜、设计器能改题并保存、登录会报错——都可以直接点。

- 入口：**`index.html`**（零依赖，双击即可打开）
- 外发单文件：**`standalone.html`**（由 `build.mjs` 内联生成，同样双击可用）
- 设计规范：`../../docs/UI-UX-V6-设计系统.md`
- 唯一数值真源：`assets/tokens.css`

> 需要 Chrome / Edge / Safari 等现代浏览器。`file://` 下也能跑；`localStorage` 不可用时
> 只是不记忆数据，不影响演示。

---

## 1. 怎么用

顶部有三处操作：

| 操作 | 说明 |
| --- | --- |
| `作答端 / 管理端 / 登录` | 切换端。作答端是 390×780 手机框，管理端是 1320×880 浏览器框 |
| `屏幕目录` | 打开右侧抽屉，13 屏全览，点任意一屏直达；地址栏 hash 会同步 |
| `重置数据` | 清掉作答内容、新建的问卷、设计器改动，回到初始状态 |

- 每屏下方有一行说明：左边是屏名，右边是这一屏的设计要点。
- 地址可直接分享，例如 `index.html#/admin/designer`；刷新后仍停在原屏。
- 窗口较窄时设备框会等比缩小；管理端建议在 ≥1200px 宽的窗口里看。

## 2. 屏目录与可试的操作

### 作答端（手机框）

| # | 屏 | 可以试什么 |
| --- | --- | --- |
| 01 | 问卷封面 | 点「开始作答」进入作答；展开/收起「作答说明」；「看看我的记录」进记录页 |
| 02 | 作答页 | 11 种题型都能操作：单/多选、文本、数字、日期、地址（三级选择弹层）、图片上传、引用选择、多行长文本；作答后进度即时更新，1.2s 后出现「已暂存 HH:MM」 |
| 03 | 作答页 · 校验失败 | 空着必答题点「提交问卷」：顶部错误摘要出现，点条目可跳到对应题；题块与选项标红；不会误跳转 |
| 04 | 提交信息 | 姓名/部门/手机号校验；「信息如何使用」说明；提交后 600ms loading → 结果页 |
| 05 | 作答结果 | 分数环 900ms 一次到位；答对/答错/未答统计；逐题回顾可折叠；底部动作（再测一次 / 查看记录 / 分享） |
| 06 | 作答记录 | 草稿 / 已提交筛选；「继续作答」回作答页；「查看结果」进结果页 |
| 07 | 我的测评 | 未登录与已登录两种状态；「登录」进移动登录 |
| 08 | 移动登录 | 账号密码、明文切换、回车提交、错误态抖动；演示账号 `linyizhou` / `123456` |

### 管理端（浏览器框）

| # | 屏 | 可以试什么 |
| --- | --- | --- |
| 09 | 问卷列表 | 输入「健康」搜索（真实过滤）；切状态分段；行 hover 出现「编辑 / 作答」，`⋯` 常驻菜单（复制、删除）；翻页；右上「新建问卷」弹层创建后新行置顶 |
| 10 | 列表加载 | 首屏骨架：表头与页头结构保留，内容为骨架条 |
| 11 | 可视化设计器 | 左侧目录点题 → 中间纸面高亮 → 右侧属性同步；改标题/说明/必填/计分，纸面即时更新；选项可增删与上下移；题型可切换；「添加题目」「删除题目」；「预览」打开手机预览（Esc 关闭）；「保存」写回列表，「发布」改状态 |
| 12 | 桌面登录 | 左右分栏；演示账号 `admin` / `123456`；错误密码有行内错误；登录成功进列表 |
| 13 | 设计系统 | 活的规范页：色板与对比度（运行时读取令牌并计算）、字阶、间距圆角阴影、按钮/输入/状态/动效/图标、双端密度对照 |

### 键盘与焦点

- Tab 可走完所有主流程，`focus-visible` 有 2px 靛蓝焦点环；
- 弹层内 Tab 循环、Esc 关闭、关闭后焦点回到触发元素；
- 作答页的选项组用方向键切换、Space 选中；
- `prefers-reduced-motion: reduce` 时全部动效降为瞬时。

## 3. 设计决策（三句话）

1. **现代、干净、克制**：冷白画布 + 白色纸面 + 墨黑文字，不用纹理、不用暖色、不用衬线；
   质感来自字号/字重/间距/1px 描边/克制的阴影。
2. **唯一一笔靛蓝**，只给进度、选中、主行动；语义色只在真表达状态时出现。
3. **两端一脉**：作答端宽松（行高 1.7、控件 44），管理端紧凑（行高 1.5、控件 40），
   颜色、圆角、图标、状态语义完全一致。

设计过程：V6.0「纸墨」（暖纸 + 衬线）在第一轮评审被否决后改为 V6.1「清简」。
否决理由与修订细节见规范文档 §1.2 与设计系统屏「V6.1 修订」一节。

```

│   ├── admin.css/js      # 管理端 4 屏
│   └── system.css/js     # 设计系统屏
├── scripts/
│   ├── qa.mjs            # 逐屏截图 + 控制台错误收集
│   ├── flow.mjs          # 三条主流程交互回归（20 项断言）
│   └── dom.mjs           # 打印某屏可交互元素（排查选择器）
└── _shots/               # 截图产物（13 屏）
```

## 5. 命令

```bash
# 重新生成单文件版
node design/prototype-v6/build.mjs

# 逐屏截图（1440×900，产物到 _shots/）
node design/prototype-v6/scripts/qa.mjs
node design/prototype-v6/scripts/qa.mjs --only cover,survey
node design/prototype-v6/scripts/qa.mjs --width 430 --height 900

# 交互回归：作答 / 管理 / 登录三条链路
node design/prototype-v6/scripts/flow.mjs
```

依赖本机 Chrome / Edge（复用仓库 `scripts/lib/chrome.mjs` 的定位逻辑），
不启动 dev server、不占用 `pnpm dev` 的端口。

## 7. 已知边界

- 数据是演示数据，不连真实网关；图片上传只做本地预览。
- 管理端列表的「作答」动作会跳到作答端演示数据，不携带该问卷真实配置。
- 不覆盖微信小程序真机、公众号 webview 的真实键盘与安全区差异。
- 未做暗色主题与国际化。
- 窄窗口下管理端设备框会等比缩小到不易阅读，这是设备框的表现方式，不是布局缺陷。
