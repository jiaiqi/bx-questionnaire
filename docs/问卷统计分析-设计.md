---

## 1. 为什么不是照搬参考页

参考工程的两张结果页是**作答者视角的报告**：一张装饰性 SVG 大图 + 评估建议列表，数据只到
`srvdaq_activity_sug_select` 的文案。它解决的是「答完给我一句结论」，不是「运营怎么看这批数据」。

本项目的统计页面向**管理端运营**，要回答四个问题：

1. 收了多少份？完成率多少？—— 概览 KPI
2. 什么时候收的？有没有集中爆发/断档？—— 提交趋势
3. 分数集中在哪一档？—— 成绩分布
4. 每道题大家怎么选的？—— 逐题分析 + 答卷明细

因此保留参考页「先给结论、再给明细」的阅读顺序，但把视觉语言换成 V6 管理端的
「数据表 + 轻图表」，不做装饰性大图。

## 2. 信息架构

```text
统计页
├─ 顶栏：返回 / 品牌 / 面包屑 / 刷新
├─ 页头：问卷标题 + 状态 + 活动号 + 回收数 + 满分
│   └─ 操作：查看问卷 / 编辑 / 导出答卷
├─ 筛选：时间范围（全部 / 近 7 天 / 近 30 天） + 作答状态（全部 / 完成 / 未完成）
├─ 概览 KPI（4 格）
│   ├─ 回收份数（当前筛选）
│   ├─ 完成率（完成 / 总数）
│   ├─ 平均分（最高 / 最低）
│   └─ 平均用时（仅完成）
├─ 图表（PC 两栏 / 移动单栏）
│   ├─ 提交趋势：近 14 天柱状（CSS，无图表库）
│   └─ 成绩分布：满分五等分横条
├─ 逐题分析
│   ├─ 覆盖说明：基于 N 份完整作答 + 加载更多
│   ├─ 选项题：选项分布横条（人数 / 百分比，基数为作答人数）
│   ├─ 数字题：均值 / 中位数 / 最小 / 最大 + 区间分布
│   └─ 文本题：默认 3 条样本，可展开；显示昵称而不是批次号
├─ 答卷明细：昵称 / 状态 / 得分 / 提交时间 / 用时，前端分页
└─ 页脚：统计口径说明
```

## 3. 数据与覆盖范围

### 3.1 三层数据，互不阻塞

| 层 | 服务 | 用途 | 是否必需 |
| --- | --- | --- | --- |
| 配置 | `srvdaq_init_view_select`（plain） | 标题、满分、题目/选项定义 | 是 |
| 记录 | `srvdaq_record_reply_select` | KPI、趋势、成绩分布、答卷明细 | 是 |
| 逐题明细 | `srvdaq_record_reply_merge_select` + `group` | 选项分布、数字区间、文本答案人数 | 否 |

### 3.2 服务端聚合（2026-10-23 升级，group 实测可用）

平台 select 支持 `group`（官方契约，已在本环境实测）：

| 能力 | 写法 |
| --- | --- |
| 分组 | `{colName:'state', type:'by'}` |
| 计数 | `count_all`（含 null）/ `count`（排除 null）/ `distinct_count` |
| 数值 | `sum` / `avg` / `min` / `max` |
| 时间 | `by_date` / `by_month` / `by_week` / `by_year` / `by_hour` … |

当前页面用一次 `multi/select`（4 个子请求）拿全 KPI / 趋势 / 分数分布 / 批次列表：

1. `state by` + `count_all`（总数）+ `count(score)` / `avg` / `sum` / `max` / `min`（分数）；
2. `create_time by_date` + `count_all` → 按天趋势；
3. `score by` + `count_all`（仅完成）→ 精确分数分布；
4. `fill_batch_no by`（仅完成）→ 参与逐题统计的批次。

逐题分布：
- `srvdaq_record_reply_merge_select` **没有 `activity_no`**，只能按 `fill_batch_no` 过滤；
- 实测 `fill_batch_no in (...)` 返回「系统繁忙」，`relation_condition OR` 返回空，因此按批次逐个查；
- 用 `multi/select` 把 **20 个批次合成一次 HTTP**（不是 20 次往返），每个子请求
  `group item_title + svalue + count_all`，响应只有「题目标题 / 答案 / 人数」；
- 默认最多覆盖 **200 份完成答卷**，页面显示覆盖范围；文本题只保留去重后的答案与人数（没有逐份昵称，属聚合口径取舍）。

其它口径：
- 平均用时服务端 `group` 无法做时间差，仍由已加载记录补算；
- 记录超过 1000 份时提示「仅统计最近 1000 份」（明细表与导出）。

### 3.3 作答值口径

- 选项题：`svalue` 按 `option_value / option_no / 选项文案 / 展示序号` 匹配；多选题每人每个选项一行，累加即选择次数；
- 多选题百分比基数为**该题作答人数**（不是总人数），与「未答 N」并列展示；
- 数字题：按「值 × 人数」还原加权分布，再去掉平台 5 位小数；
- 文本题：按去重答案 + 人数展示，默认 3 条、可展开；没有逐份时间/昵称。

## 4. 视觉与交互

- 沿用 V6 管理端「清简」：`--bx-bg` 画布、白色卡片、14px 卡片圆角、1px 描边、
  `--bx-primary` 数据色；不引入新色板。
- 图表全部 CSS：
  - 趋势 = flex 柱状（柱高按最大值等比，零值画 2px 灰线）；
  - 选项/成绩/数字区间 = 轨道 + 填充条（`width: percent`）；
  - 不引入 ECharts（体积 + 小程序 canvas 适配成本），也不使用 `<svg>`（小程序不支持）。
- 可访问性：筛选是 `role="group"` + `aria-pressed`；趋势柱有 `aria-label`「日期 + 份数」；
  样本展开按钮有 `aria-expanded`；表格移动端重排为「主信息 + 状态 / 时间 + 用时」。
- 响应式：
  - ≥900px：KPI 四栏、图表两栏、表格五列；
  - <900px：KPI 两栏、图表单栏、表格两行式；
  - ≤520px：仍保持 KPI 两栏（一列会把 4 个指标拉成 4 屏）。

## 5. 空态 / 错误态 / 极限态

| 状态 | 表现 |
| --- | --- |
| 还没有回收 | BxEmpty「还没有回收记录」+ 引导分享 |
| 加载失败 | BxEmpty + 错误原文 + 重试 |
| 明细部分失败 | 不阻断主统计，顶部红字「N 份明细加载失败」 |
| 无分值问卷 | 成绩分布显示「这份问卷没有可统计的分值」 |
| 记录 > 1000 | 提示「仅统计最近 1000 份」 |
| 明细 > 400 | 「加载更多」隐藏，说明已达上限 |

## 6. 与版本隔离/结果页的关系

- 统计页只读，不写任何配置；
- 当前保存是原地更新，如果问卷在「进行中」被改题，历史作答的展示口径会变。
  统计页本身无法修复这一点，版本隔离方案见 `docs/技术优化建议.md` §9；
- 后续可在统计页加「导出 CSV → 本地留存」作为口径快照的兜底。
