## 二、跨页面共性问题（单独修某一页只是治标）

1. **参数缺失时返回键把用户送进错误页**：`coverUrl('')` 会返回不带参数的封面路径，而 `BxNavBar` 只要地址非空就 `reLaunch`。`RecordHistory`、`survey/result`、`assessmentResult` 三处都是这么写的；`useResultPage.goHome` 已经修过同一类缺陷。
2. **匿名/登录的服务边界没写进设计**：填写端大量是匿名场景，但只有 `record_reply_select`、`activity_sug_select`、`activity_result_submit` 匿名可用；`activity_cfg_select`、`rule_sug_select`、`score_sug_select`、`merge_select` 都要登录。涉及数据源的建议都已标注可用性。
3. **同一份记录在不同页面口径不一致**：`RecordList` 认为「非未完成即已提交」并显示 `start_time`，`couple` 硬过滤 `state='完成'` 并显示 `end_time` —— 同一批数据「有/没有」「时间不一样」。
4. **草稿改本机后，记录侧还在讲服务端的「草稿」故事**：`result_save` 已不调用，但记录页的「草稿」分段与答题页的 `restoreDraftBatch` 仍按 `state='未完成'` 工作。
5. **平台已有能力大量闲置**：
   - `act_option` 编辑器枚举仍是 `['评分','提交确认']`，平台实际是 `['评分','不评分']` —— **配不出「不评分」问卷，还会写出平台不认的值**（`domain/editor/enums.ts:46-47`）。
   - `modify_after_submit` / `modify_periond` 可配「提交后允许修改」，填写端完全没消费。
   - `bxdaq_activity_score_sug`（分数区间结果说明）、`bxdaq_activity_rule_sug.no_sug_desc`（未命中规则文案）都没被结果页用上。
   - `srvdaq_item_cfg_templ_select`（题库）、`srvdaq_activity_cfg_deep_copy`（复制问卷）管理端都没接。

## 三、建议的处理顺序

1. **先修 6 个 P0** —— 都是「丢数据 / 白填 / 登录后落错页」，与体验无关，属于正确性问题。
2. **统一跨页口径** —— 返回键兜底、记录状态与时间口径、草稿语义（本机草稿要在记录页可见）。
3. **接平台能力** —— `score_sug` 结果说明、`modify_after_submit` 修改作答、`item_cfg_templ` 题库、`deep_copy` 复制。
4. **最后打磨 P2** —— 空态、加载态、文案、无障碍。

## 四、填写端页面（6 个）


### 本组概览

本组 6 个页面全部是**作答者**视角：它们不产生配置，只消费 `bxdaq_activity_cfg` 的活动行、`bxdaq_record_reply` 的记录行与五张 `bxdaq_storage_*` 明细。结构上可分三类：**答题**（`survey/survey`，主体是共用的 `QuestionnaireRunner`）、**列表**（`history/history` 与 `survey/history`，共用 `RecordHistory` + `RecordList`；`couple` 是它的登录态聚合变体）、**结果**（`survey/result` 与 `assessmentResult`，共用 `SuggestionPanel`）。

四条跨页面的共性问题，单独修某一页都只是治标：

- **参数缺失时返回键会把用户送进错误页**：三个页面把 `coverUrl(activityNo)` 直接当 `BxNavBar` 兜底地址，而 `withQuery` 会把空值参数过滤掉，`coverUrl('')` 因此返回**不带参数的** `/pages/questionnaire/cover/index`，`BxNavBar` 只要地址非空就 `reLaunch`（`src/domain/questionnaire/routes.ts:44-60`、`src/components/base/BxNavBar.vue:57-60`、`src/components/questionnaire/RecordHistory.vue:52`、`src/pages/questionnaire/survey/result.vue:31`、`src/pages/questionnaire/assessmentResult/assessmentResult.vue:30`）。这与 `useResultPage.goHome` 已经修过的缺陷是同一类（`src/composables/useResultPage.ts:396-403`）。
- **匿名/登录可用服务的边界没有被写进设计**：填写端大量场景是匿名的，但只有 `srvdaq_record_reply_select`、`srvdaq_activity_sug_select`、`srvdaq_activity_result_submit` 是匿名可用（`docs/平台-问卷表与服务清单.md:69`、`:76`、`:89`）；`srvdaq_activity_cfg_select`、`srvdaq_activity_rule_sug_select`、`srvdaq_activity_score_sug_select`、`srvdaq_record_reply_merge_select` 都要登录（`:53`、`:77`、`:90-91`）。下面的建议在涉及数据源处都标注了它是匿名可用、还是仅登录态可用，避免给出「匿名页调登录服务」这种落不了地的方案。
- **同一份记录在不同页面的口径不一致**：`RecordList` 认为「非未完成即已提交」并显示 `start_time`（`src/components/questionnaire/RecordList.vue:82-90`、`:414`），`couple` 硬过滤 `state='完成'` 并显示 `end_time`（`src/pages/questionnaire/couple/couple.vue:69`、`:91`）；结果是同一批数据在不同页面「有/没有」「时间不一样」。
- **草稿改成只写本机后，记录侧仍在讲服务端的「草稿」故事**：`srvdaq_activity_result_save` 自 2026-11-06 起不再调用（`src/api/daq/record.ts:7-9`、`docs/平台-问卷表与服务清单.md:70`），但记录页的「草稿」分段/「继续作答」文案、以及答题页的 `restoreDraftBatch` 都还按服务端 `state='未完成'` 工作（`RecordList.vue:57-61`、`:217-219`、`src/components/questionnaire/QuestionnaireRunner.vue:416-437`）。

统计：**P0 2 条、P1 28 条、P2 13 条**（共 43 条）。

#### 作答记录（`pages/questionnaire/history/history`）

- **现状**：页面壳只做路由与下拉刷新声明（`src/pages/questionnaire/history/history.vue:12-17`），正文是 `RecordHistory` + `RecordList`；按 `srvdaq_record_reply_select` 分 20 条一页拉取（`src/api/daq/record.ts:105-108`、`RecordList.vue:50`），在本地按归属过滤他人记录（`src/domain/questionnaire/records.ts:46-51`），并提供「全部/已提交/草稿」的**客户端**分段筛选与分片渲染（`RecordList.vue:52-90`、`:103-112`）。

- **问题与建议**：
  - [P1] 筛选与条数只覆盖「已加载的前 N 条」：分段筛选是对 `visibleRows` 做本地 `filter`，「20 / 20 条」用的是渲染窗口与已加载数，而服务端返回的 `page.total` 只被用来判断「还有没有下一页」 → 建议用 `envelope.page.total` 显示「共 N 条」，并把筛选下推为服务端 `state` 条件（`recordReplySelect` 已支持该参数）（依据：`src/components/questionnaire/RecordList.vue:83-90`、`:370`、`:163-164`；`src/api/daq/record.ts:90-92`）
  - [P1] 列表没有任何排序保证：该服务不接受 `order`（传任何排序字段都返回 0 条且不报错），前端又是「按响应顺序追加」→ 刚提交的记录可能排在第 3 页，用户会以为没提交成功（依据：`src/api/daq/record.ts:101-104`；`RecordList.vue:161`）
  - [P1] 已完成记录显示的是「开始作答时间」却贴在「已提交」旁边：同行渲染的是 `start_time`，而同类列表 `couple` 用 `end_time ?? start_time` → 用户读到的「提交时间」其实是开始时间，且两页口径不同（依据：`RecordList.vue:411-416`；`src/pages/questionnaire/couple/couple.vue:91`；`src/domain/questionnaire/format.ts:49-53`）
  - [P1] 「草稿」分段与「继续作答」已与服务端事实脱节：`result_save` 下线后不再产生 `state='未完成'` 记录，新版用户填一半退出，本页看不到任何草稿，`isDraft` 只会命中 2026-11-06 之前的历史脏记录 → 建议把本机草稿（`bxq:draft_answers:<activity_no>`，`src/utils/storage.ts:36-38`）作为一条「未提交（本机草稿）」行显式渲染在列表顶部，带保存时间与「继续作答」，并标注来源是本机还是服务端（依据：`src/api/daq/record.ts:7-9`；`RecordList.vue:57-61`、`:78-80`、`:217-219`；`docs/平台-问卷表与服务清单.md:70`）
  - [P1] 空态主操作不看活动闸门：按钮固定拼 `status:'进行中'` 直接跳作答页，既不判断 `answer_times`（后端不强制，同账号可重复提交生成新批次），也不判断活动是否已结束或需要登录 → 用户点进去可能落到只读卷、或在提交时才被 `0011` 拒（依据：`RecordList.vue:285-288`；`docs/平台-问卷表与服务清单.md:122-131`）
  - [P1] 未登录且首页 20 条全是他人记录时，用户自己的记录不可达：空态分支里没有「加载更多」，内容短于视口时页面也不会触发 `onReachBottom` → 只能去登录（依据：`RecordList.vue:321-336`、`:435-461`；`src/composables/useRecordHistoryPage.ts:55-57`）
  - [P1] 参数缺失时返回键把用户送进错误页：兜底地址用 `coverUrl(activityNo)`，`activityNo` 为空时 `coverUrl('')` 返回无参路径，`BxNavBar` 仍会 `reLaunch` → 「缺少活动编号」错误页（依据：`src/components/questionnaire/RecordHistory.vue:52`；`src/domain/questionnaire/routes.ts:44-60`；`src/components/base/BxNavBar.vue:57-60`）
  - [P2] 记录行第三行常驻 32 位批次号：结果页已按需求去掉批次号（`src/pages/questionnaire/index/result.vue:251`），列表里仍把它当主要信息之一，对用户无意义且挤占行动入口（依据：`RecordList.vue:427-432`）
  - [P2] 未登录提示条的「去登录」与筛选分段触摸目标偏小：分别为 32px / 28px 高，低于本项目其余页面统一的 44px 约定（依据：`RecordList.vue:526-533`、`:568-571`、`:787-792`；对比 `src/pages/questionnaire/couple/couple.vue:506-515`）

- **平台能力可借力**：
  - `srvdaq_record_reply_select` 是**匿名可用**的（`docs/平台-问卷表与服务清单.md:76`），`colNames:['*']` 的 `t.*` 里还有 `company` / `survey_result` / `survey_suggestion`（同上）—— 当前行模板只用了 `title`/`score`/`state`/时间/批次（`RecordList.vue:405-432`），同一份响应就能补「所属单位」与「建议摘要」；**匿名场景尤其需要**：匿名提交每次都会生成新的 32 位随机 `user_no`（`docs/平台-问卷表与服务清单.md:138-141`），只有 `company` 能帮用户认出自己那条记录。
  - `answer_times`（默认「1次」、后端不强制，只能前端做入口隐藏，`docs/平台-问卷表与服务清单.md:122-126`）正好用在本页空态按钮与「去答一份问卷」上。
  - `bxdaq_classify.number` 是**未被维护的冗余计数**，不能当权威条数（`docs/平台-问卷表与服务清单.md:149`）；要显示总数就用 `page.total`，别去读分类表的 `number`。

#### 调研答题（`pages/questionnaire/survey/survey`）

- **现状**：页面只有 `onLoad` 读 `activity_no`/`formType`/`fill_batch_no`，并把 `result-path` 指向 `survey/result`（`src/pages/questionnaire/survey/survey.vue:8-33`）；主体是共用的 `QuestionnaireRunner`（卷首与 `answer_times` 展示、逐个/整卷两种展示方式、本地草稿、提交后 `redirectTo` 结果页）。

- **问题与建议**：
  - [P0] 提交会写进一条**历史**「未完成」记录：`restoreDraftBatch` 仍按 `state='未完成'` 从服务端取批次号写进 `session.fillBatchNo`，提交时把它作为 `fill_batch_no` 传下去 → 草稿服务下线后服务端不再产生新的未完成记录，这条路径现在只会捞到**旧的历史草稿**，今天的新作答会被续写进那条旧记录（时间/归属错乱），且该查询用 `rownumber:1` 而服务端不接受 `order`，捞到的还不一定是最新那条（依据：`src/components/questionnaire/QuestionnaireRunner.vue:416-437`、`:589`；`src/api/daq/record.ts:7-9`、`:101-104`；`docs/平台-问卷表与服务清单.md:69-70`）
  - [P0] 「登录访问」活动可以填完整卷、提交时才被 `0011` 拒：活动行里有 `perm_type`（`src/api/daq/types.ts:77`），`QuestionnaireRunner` 全程没有任何判定；请求层收到 `0011` 只 `notifyParent('TICKET_EXPIRED')`，不跳登录 → 用户白填一整份，答案只剩本机草稿，且页面没有登录入口（依据：`QuestionnaireRunner.vue:330-390`、`:587-633`；`src/utils/request/index.ts:144`；`docs/平台-问卷表与服务清单.md:128-131`）
  - [P1] 提交确认写死「提交后无法修改」，忽略活动配置 `modify_after_submit`：设计器能编辑该字段（`src/domain/editor/document.ts:98`、`:221-223`），平台表也有该列（`docs/平台-问卷表与服务清单.md:17`），填写端零读取 → 活动允许修改时，页面给的是**错误信息**（依据：`QuestionnaireRunner.vue:570`；`src/api/daq/types.ts:98`）
  - [P1] `answer_times` 只展示、不拦截：卷首把「作答次数」渲染出来，提交前却不校验本账号是否已提交过 → 同一账号会静默生成第二条记录，而页面提示的仍是「1次」（依据：`QuestionnaireRunner.vue:807-810`；`docs/平台-问卷表与服务清单.md:122-126`）
  - [P1] 点「继续作答」进去可能是一张全空卷，且没有任何说明：`init` 先按 `type=use` + 批次号取 `user_data`，失败退回 `plain`，再退回本机草稿；三条路都空时页面只显示「已答 0」，不区分「这次本来就没答」与「答案取不回来」（`type=use` 要求调用者是活动创建人，非创建人必然失败）（依据：`QuestionnaireRunner.vue:355-389`、`:377-389`；`docs/验收清单.md:1379-1382`）
  - [P1] 小程序分享能力缺失：调研页没有 `onShareAppMessage` / `onShareTimeline`，也没有 `enableShareTimeline` 页面配置；同为 Runner 入口的 `index/index` 两样都有 → 从分享进来的调研问卷，用户无法再次转发（依据：`src/pages/questionnaire/survey/survey.vue:8-23`；`src/pages/questionnaire/index/index.vue:39`、`:45-46`、`:61-70`；`src/pages/questionnaire/cover/index.vue:199-208`）
  - [P2] 两个答题页的壳已经开始漂移：`index/index` 暴露 `runner` ref 取活动标题供分享使用，`survey/survey` 没有；而两页的注释本身声明「差异仅在路由与结果页指向」（依据：`src/pages/questionnaire/survey/survey.vue:4-5`、`:26-33`；`src/pages/questionnaire/index/index.vue:73-80`）
  - [P2] 空态只给文案不给动作：缺 `activity_no` 时提示「请从活动入口或二维码重新进入」，但没有返回/关闭按钮，而同项目其他空态都配了主操作（依据：`survey.vue:34-36`；对比 `RecordList.vue:328-335`）

- **平台能力可借力**：
  - 活动行里已经带了 `perm_type` / `answer_times` / `modify_after_submit` / `passing_mark` / `submit_label` / `item_disp_way`（`src/api/daq/types.ts:74-98`），当前填写端只用到了 `submit_label` 与 `answer_times` 的展示（`QuestionnaireRunner.vue:162`、`:807-810`）；上面 4 条 P0/P1 全部是「字段已在手边、没有消费」。
  - 计分口径必须用 `act_option` 的**包含匹配且先判「不评分」**，缺失时回退 `total_points > 0`（`docs/平台-问卷表与服务清单.md:111-114`，正确实现见 `src/composables/useResultPage.ts:309-318`）；调研页若要在卷首说明「本次计分/不计分」，请复用这份判据，不要自己看 `total_points`。
  - `answer_times` 的闸门只能在填写端做（后端不强制），而 `srvdaq_record_reply_select` 匿名可用（`docs/平台-问卷表与服务清单.md:76`）—— 因此「本账号/本机是否已作答」这个判断，匿名态用本机批次号（`src/utils/storage.ts:91-114`）、登录态用 `user_no`，两条路都已有现成基础。

#### 调研结果（`pages/questionnaire/survey/result`）

## 五、管理端页面（4 个）


### 本组概览

本组覆盖四个页面：**问卷列表**（`pages/editor/list/index`，启动页）、**可视化设计器**（`pages/editor/design/index`，配合 `EditorCanvas` / `EditorItemPanel` / `EditorActivityForm` / `DesignerPreview` / `useEditorDocument` / `useEditorDesign`）、**问卷统计**（`pages/editor/stats/index`，配合 `useSurveyStats` / `domain/stats/compute`）、**登录**（`pages/login/index` + `LoginScreen`）。共同背景见 `docs/平台-问卷表与服务清单.md`（下称「平台清单」）。

整体判断：这几页的**版式、空态、错误态、无障碍基线**已经做得比常规后台细（表格降级、骨架、焦点环、`aria-*`、离线条都在），主要缺口集中在三类：

1. **数据不丢与状态可感知**：设计器没有本机草稿、没有刷新/会话过期保护；保存后编辑位置丢失；发布成功与保存成功在 UI 上完全一样。
2. **平台已有能力没接到管理端**：题库（`item_cfg_templ_select`）、建议规则/分数段说明（`rule_sug` / `score_sug`）、分类树筛选、`deep_copy`、`record_reply_with_fill_select` 等都能用，但目前只用了最基础的三张配置表读写。
3. **统计口径存在两处会明显算错的点**：逐题「未答」分子分母不同源、以及依赖 `record_reply_merge_select` 时对多选的假设与平台实测不符。

优先级按任务定义：`P0` 丢数据/阻断流程/明显错误；`P1` 明显影响体验或高频场景不顺；`P2` 打磨项。本组共 **4 条 P0、23 条 P1、22 条 P2**。

#### 登录（`pages/login/index`）

- **现状**：`LoginScreen` 承担全部 UI（移动单列 / H5 宽屏分栏），`useLogin` 负责校验、防重、调 `srvsso_*` 登录、写 `session` 与「记住账号」；支持密码明文切换、忘记密码说明弹层（含复制账号）、错误抖动与 `aria-live` 提示，登录成功后 `reLaunch` 到 `redirect`。

- **问题与建议**：
  - [P0] 兜底回跳指向**必须带 `activity_no`** 的答题页：任何没带 `redirect` 的登录（从列表点「登录」、直接打开登录页、`redirect` 被安全校验拒绝）都会落到「缺少活动编号」 → 兜底改成本应用首页 `editorListUrl()`，与 `pages.json`/`definePage` 的 home 保持一致（依据：`src/pages/login/index.vue:20-21`、`32-37`、`48-50`；`src/pages/questionnaire/index/index.vue:75-83`；`src/pages.json:14-20`）。
  - [P2] 登录页不告诉用户「登录后会回到哪一页」，会话过期回跳时用户不知道自己在为什么而登录（`redirect` 只被校验、没有被展示）→ 展示目标页摘要（如「登录后继续编辑问卷」），无法识别时回退到通用文案（依据：`src/pages/login/index.vue:32-37`；`src/components/auth/LoginScreen.vue:199-201` 只有一行通用 notice）。
  - [P2] 错误只落在表单底部一行 + 输入框抖动，没有绑定到具体字段：`input` 无 `aria-invalid`、错误文本无 `aria-describedby`，读屏只听到整体提示 → 按 `useLogin` 返回的 `field` 给对应输入框加 `aria-invalid`、把错误 id 关联上，并把焦点送回出错字段（依据：`src/components/auth/LoginScreen.vue:285-291`、`203-216`、`218-231`；`src/composables/useLogin.ts:37-48` 已给出 `field`）。
  - [P2] 账号/密码输入框没有 `autocomplete`（`username` / `current-password`），H5 端密码管理器不工作 → 补 `autocomplete` 与 `name`（依据：`src/components/auth/LoginScreen.vue:205-215`、`221-231`）。
  - [P2] 前端强制密码 ≥6 位，若平台存在更短的历史密码会被本地拦下且提示「密码至少 6 位」→ 以平台返回为准，或只在「新设密码」场景校验（依据：`src/composables/useLogin.ts:16-17`、`44-46`）。
  - [P2] 没有自动聚焦：H5 首次进入需手动点账号框，记住账号时也该直接聚焦密码 → 挂载后按 `rememberedUser` 决定聚焦哪个框（依据：`src/components/auth/LoginScreen.vue` 无自动聚焦逻辑，仅有 `useDialogFocus` 服务于忘记密码弹层）。
  - [P2] 平台连续失败会锁号 1 小时，但界面只有一次错误文案，没有冷却或剩余次数提示 → 错误文案补一句「连续失败会锁定账号」，或做倒计时（依据：`src/components/auth/LoginScreen.vue:10-13` 注释已提到锁号；`src/composables/useLogin.ts:87-91` 只透传文案）。
  - [P2] 忘记密码弹层把联系方式写死（内线 8100），换租户/园区要改代码 → 提到配置常量或环境变量（依据：`src/components/auth/LoginScreen.vue:334`）。

- **平台能力可借力**：
  - `srvuser_login` 的响应里已带 `userInfo`（`useLogin` 已 `session.setUserInfo`），但管理端无人展示 —— 在列表页顶栏显示当前账号并配「退出登录」，与列表页那条 P1 是同一处实现。
  - `perm_type = 登录访问` 的活动闸门（平台清单 §三）—— 登录页可据此解释「这份问卷需要登录后填写」，而不是只给通用提示。
  - `srvsso_*` 的错误码 —— 已原样透出，建议按码映射「密码错误 / 账号锁定 / 票据过期」三类可操作提示（当前只透传原文）。

#### 封面页（`pages/questionnaire/cover/index`）

**现状**：`init_view_select` 拉活动配置，展示标题、`summary` 副标题、`remark` 描述、2×2 信息网格、可展开的「作答说明」、通栏「开始作答」；宽屏展示二维码（可点击放大）；已补小程序分享回调。

**问题与建议**

- [P1] 只判 `status === '已结束'` 决定按钮文案，**「未开始」的活动也显示「开始作答」**，点进去才可能发现不能答 → 按三态区分：未开始显示「尚未开始」+ 开始时间，进行中才给主按钮（依据：`cover/index.vue` 的 `ended` 与模板 `v-if="!ended"`）。
- [P1] 平台 `modify_after_submit` / `modify_periond` 可配「提交后允许修改」，**填写端完全没实现**；已提交用户回到封面仍是「开始作答」，点进去重复作答 → 允许修改时应显示「修改作答」并带上原批次号（依据：`api/daq/types.ts:98` 声明了字段，`src` 内除编辑器外无消费）。

#### 答题页（`pages/questionnaire/index/index` + `QuestionnaireRunner`）

**问题与建议**
