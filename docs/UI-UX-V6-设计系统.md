## 1. 设计立场

### 1.1 产品约束

问卷产品有四个硬约束，决定了界面不能自由发挥：

1. **作答者只来一次**：没有学习成本，界面必须一眼看懂「这是什么、要答多久、怎么提交」。
2. **内容可能敏感**：健康测评与员工满意度会触及情绪，界面不能有压迫感、不能像考试系统。
3. **多端同源**：H5、公众号、微信小程序、管理端共用一套视觉；小程序不能加载外链字体。
4. **管理者高频**：列表与设计器是每天用的工具，密度与效率优先，装饰必须让路。

### 1.2 为什么从「纸墨」改为「清简」

V6.0 曾尝试「一份认真排版的纸质问卷」：暖白纸底、墨色文字、衬线标题。
第一轮评审被否决，原因是：

- 暖纸底 + 衬线读起来像**文艺模板**，不像一个要长期使用的现代工具；
- 纸质感靠纹理与暖色撑着，在低分屏、小程序 webview、暗光环境下会发灰；
- 管理端需要高密度与快速扫描，纸张隐喻没有提供任何效率帮助。

V6.1「清简」保留了 V6.0 的结构性结论（单一强调色、两端同源、安静的运动），
换掉了气质：**冷白画布、白色纸面、墨黑文字、无衬线排版、唯一一笔靛蓝**。

「简约而不简陋」的落点不是装饰，而是：

- 每屏只有一个主行动，其余动作降级；
- 字号/字重/行高/间距四件事撑起层级，不靠色块；
- 1px 描边、克制的阴影、完整的状态设计（hover / focus / active / disabled / error）；
- 动效只解释状态变化，不表演。

### 1.3 五条原则

1. **层级来自排版**：字阶六档、字重三档、8pt 间距；不用彩色卡片分区。
2. **一处强调**：靛蓝只用于进度、选中、主行动三件事；语义色只在真表达状态时出现。
3. **安静的运动**：120 / 180 / 260ms 三档，只做状态过渡；禁止入场编排。
4. **两端一脉**：作答端宽松（行高 1.7、控件 44px），管理端紧凑（行高 1.5、控件 40px），
   颜色、圆角、图标、状态语义完全一致。
5. **可验证**：对比度、触摸目标、焦点可见性都有硬指标（见 §8），不靠「看起来还行」。

### 1.4 与 V2「墨蓝·静卷」的关系

V2 已落地在 `src/`，V6 是它的升级而不是推倒：

| 结论 | V2 | V6 | 处置 |
| --- | --- | --- | --- |
| 单一品牌色、其余中性 | ✅ | ✅ | 保留，色相更亮更现代 |
| 语义色三件套（文字 + 浅底 + 描边） | ✅ | ✅ | 保留 |
| 六档字阶 / 四级文字 | ✅ | ✅ | 保留，字号收紧一档 |
| 题目容器化、整行选项、吸顶进度 | ✅ | ✅ | 保留 |
| 中性冷灰底 | `#F2F4F7` | `#F5F6F8` | 更白、更干净 |
| 主色 | `#2C46C8`（深靛） | `#3B4EDB`（亮一档） | 更现代，白字 6.37:1 |
| 卡片圆角 16 / 控件 12 | 16 / 12 | 14 / 10 | 更利落 |
| 控件高度 48 | 48 | 44（管理端 40） | 触摸目标仍 ≥44 |
| 管理端表格 13px | — | `.dense` 13px | 新增密度层 |

### 2.3 语义色

| 语义 | 文字 | 浅底 | 描边 | 白底对比 | 浅底对比 |
| --- | --- | --- | --- | --- | --- |
| 成功 | `--c-ok` `#0F7A5A` | `#ECF7F2` | `#B3DDCD` | 5.31:1 | 4.85:1 |
| 警告 | `--c-warn` `#A34A08` | `#FDF5EA` | `#EFD3AC` | 5.93:1 | 5.49:1 |
| 危险 | `--c-danger` `#C22F24` | `#FEF3F2` | `#F4C7C3` | 5.64:1 | 5.18:1 |

只表达真实状态（提交成功、草稿未提交、校验失败），不得用于装饰；状态不能只靠颜色，
必须同时有文字或图标（管理端状态列 = 圆点 + 文字）。

### 2.4 遮罩与焦点

- `--c-scrim` `rgba(20,24,33,.34)`：弹层遮罩；`--c-scrim-soft` `.22`：抽屉遮罩。
- 焦点环使用 `--c-accent`（2px 描边 + 2px offset，非文本对比 6.37:1 ≥ 3:1）。
- `--c-focus` `#8B96EE` 是深色/图片底上的浅色备选，**本版未启用**。

### 2.5 主题

本期只做浅色。健康测评不再用独立青色主题（V2 的 `data-theme="health"` 不再需要），
成功/危险/警告已足够表达结果语义；若将来要做深色，只覆盖 §2.1–§2.4 的变量，不改组件。

## 3. 字体与字阶

### 3.1 字体栈

```scss
--font-sans: 'PingFang SC', 'HarmonyOS Sans SC', 'MiSans', 'Source Han Sans SC',
  'Noto Sans CJK SC', 'Microsoft YaHei', system-ui, -apple-system, 'Segoe UI', sans-serif;
```

- **不加载 Web Font**：微信小程序无法加载外链字体，H5 加载会造成端间字重/行高不一致；
  中文系统字体在 iOS / Android / Windows 上差异已足够小。
- **不使用衬线**：`--font-serif` 仅为兼容旧类名而指向无衬线栈，产品 UI 不出现衬线。
- 字重只用 400 / 500 / 600：中文细体在低分屏发虚，700 在 15px 会挤。
- 所有数字（题号、分数、计数、日期、批次号）加 `font-variant-numeric: tabular-nums`。

### 3.2 字阶

| Token | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| `--fs-display` | 32 / 1.25 | 600 | 封面主标题、登录主张、结果大分数 |
| `--fs-h1` | 24 / 1.32 | 600 | 页面主标题 |
| `--fs-h2` | 19 / 1.4 | 600 | 区块标题、弹层标题 |
| `--fs-h3` | 16 / 1.5 | 600 | 题干、卡片标题、列表主标题 |
| `--fs-body` | 15 / 1.7 | 400 | 正文、选项、说明 |
| `--fs-sub` | 13 / 1.6 | 400/500 | 辅助说明、行内错误、meta |
| `--fs-cap` | 12 / 1.5 | 400 | 元信息、标签、计数（下限） |
| `--fs-micro` | 11 / 1.45 | 500 | 全大写式小标签（题号、表头），加 `.08em` 字距 |

大字号一律 `letter-spacing: -0.02em`（`--ls-tight`）；11–12px 小标签用 `--ls-wide`（`.08em`）。
管理端 `.dense` 把 `--fs-body` 覆盖为 13 / 1.5，`--fs-sub` 为 12，字号档位不变。

## 5. 组件规范

以下规范均已在原型的 `base.css` 中实现；落地时迁移到 `src/components/base`。

### 5.1 按钮

| 变体 | 视觉 | 用途 |
| --- | --- | --- |
| `.btn--primary` | 靛蓝底 + 白字 + `--sh-accent` | 每屏唯一主行动 |
| `.btn--ghost` | 白底 + `--c-line-3` 描边 | 次级行动（保存、取消） |
| `.btn--quiet` | 无底无框，hover 浅灰底 | 第三级文字操作 |
| `.btn--danger` | 危险红底白字 | 删除确认 |

- 高度 44 / 34（sm）/ 50（lg）；圆角 10；内边距 20；字重 500。
- hover 换深一档、active 下沉 1px；disabled 透明度 45% 且不响应。
- 键盘焦点：2px accent 描边 + 2px offset，不得去掉 outline。

### 5.2 输入框与字段

- 高度 44（管理端 40），圆角 10，白底 + `--c-line` 1px 描边。
- hover 描边 `--c-line-3`；focus 描边 accent + 3px `--c-accent-soft` 柔光环。
- 错误：描边 `--c-danger` + `.field__error` 文案（12px），并且 `aria-invalid="true"`。
- 占位文字用 `--c-ink-4`，只做提示，不作为 label；每个字段必须有可见 label。
- 多行文本最小高度 104，可纵向 resize；字符计数右下角 12px。

### 5.3 选项行（作答端核心控件）

- 整行可点，最小高 48，圆角 10，白底 + `--c-line` 描边。
- 未选：空心中性标记；hover：`--c-sheet-3` 浅底；选中：`--c-accent-soft` 浅靛底 +
  `--c-accent` 描边 + 实心标记；disabled：40% 不透明度。
- 单选与多选只在标记形状上不同（圆 / 方），交互一致；选中变化 120ms。
- 键盘：Tab 进入组，方向键切换，Space 选中；组容器 `role="radiogroup"` / `group`。

### 5.4 卡片、状态点、标签

- 卡片：白底、1px `--c-line`、圆角 14、`--sh-1`；管理端卡内边距 20。
- 状态点 + 文字：进行中 = accent、未开始 = warn、已结束 = ink-3；点 6px，文字 13px。
- 标签（chip）：高 26，胶囊，浅底 + 同色描边 + 同色文字；不滥用填充色。

### 5.5 开关、分段控件、进度

- 开关：轨道 36×21，滑块 17，开 = accent；必须绑定 `<input type="checkbox">` 以保证键盘与读屏。
- 分段：外框胶囊、3px 内边距、选中项白底 + `--sh-seg`；用于「全部 / 未开始 / 进行中 / 已结束」。
- 进度：2px 槽 + accent 填充，260ms 过渡；必须带 `role="progressbar"` 与 `aria-valuenow`。

### 5.6 空态、骨架、弹层、toast

- 空态：几何线稿插画（内联 SVG，72×72，`--c-line-3`）+ 一句标题 + 一句可行动提示。
- 骨架：`--c-sheet-3` 块 + 1.4s 扫光；reduced-motion 下静止。
- 弹层：遮罩 `--c-scrim` + 白面板圆角 14 + `--sh-3`；`role="dialog"` `aria-modal="true"`，
  打开时焦点进入面板、Tab 循环、Esc 关闭、关闭后焦点回到触发元素。
- toast：深墨底 + 米白字（`--c-paper`）+ 胶囊；`role="status"`；2.2s 自动消失。

## 6. 交互与动效

### 6.1 时长与曲线

| Token | 值 | 用在哪 |
| --- | --- | --- |
| `--dur-fast` | 120ms | hover、按下、选中标记 |
| `--dur` | 180ms | 屏切换、弹层进入、焦点环 |
| `--dur-slow` | 260ms | 进度、展开收起 |
| `--dur-hero` | 900ms | 结果分数环（仅一次） |

- 出场曲线 `--ease-out` `cubic-bezier(.22,1,.36,1)`；状态切换 `--ease-inout`。
- 允许：淡入 4px、按钮下沉 1px、选中标记描边、分数环、进度条、骨架扫光。
- 禁止：逐项入场编排、视差、弹跳、无限循环装饰、滚动劫持。

### 6.2 键盘契约

| 场景 | 行为 |
| --- | --- |
| 表单 | Enter 提交（登录页、提交信息页、新建弹层） |
| 弹层 | Esc 关闭；Tab 在面板内循环；焦点回触发元素 |
| 选项组 | 方向键移动，Space 选中 |
| 表格 | Tab 到行内操作；`focus-within` 同样让 hover 操作显形 |

### 6.3 降级

`prefers-reduced-motion: reduce` 时所有动画与过渡降为 1ms，分数环直接到位；
这一条写在 `base.css` 的全局规则里，组件不得重复实现。

## 8. 可访问性

### 8.1 对比度结论（WCAG 2.1）

| 组合 | 比值 | 结论 |
| --- | --- | --- |
| 主文字 / 白面 | 18.11 | AAA |
| 主文字 / 画布 | 16.75 | AAA |
| 次要文字 / 白面 | 7.56 | AAA |
| 元信息 / 白面 | 5.01 | AA |
| 元信息 / 画布 | 4.63 | AA |
| 白字 / 主色 | 6.37 | AA（大字 AAA） |
| 强调文字 / 强调浅底 | 7.52 | AAA |
| 成功 / 白面 | 5.31 | AA |
| 警告 / 白面 | 5.93 | AA |
| 危险 / 白面 | 5.64 | AA |
| 危险 / 危险浅底 | 5.18 | AA |
| 占位文字 / 白面 | 2.54 | **仅占位，不承载信息** |

### 8.2 硬指标

- 所有交互元素触摸目标 ≥ 44×44；相邻目标间距 ≥ 8。
- 焦点可见：不允许 `outline: none` 且无替代；焦点环非文本对比 ≥ 3:1。
- 状态不只用颜色：错误有文案 + `role="alert"`，状态列有点 + 文字。
- 表单：可见 label、`aria-invalid`、错误与字段关联（`aria-describedby`）。
- 图片/图表有替代文本；纯装饰 SVG `aria-hidden="true"`。
- 弹层焦点陷阱、Esc 关闭、关闭后焦点归还。

## 9. 落地映射（从 V2 到 V6）

### 9.1 令牌映射（`src/styles/tokens.scss` + `uno.config.ts` 双向同步）

> 落地实际做法：**保留 `--bx-*` 命名，只替换取值**（全仓 400+ 处引用无需改名），
> 并同步 `uno.config.ts` 的 `theme.colors.bx`。下表的 V6 列是原型命名，仅用于对照。

### 9.3 落地顺序与风险

1. **令牌先落**（含 `uno.config.ts` 与令牌一致性测试），否则组件改动无法验证。
2. 基础组件（按钮 / 输入 / 导航 / 空态 / 骨架）。
3. 作答链路（选项 → 题目卡 → 进度 → 错误摘要 → 提交/结果）。
4. 管理端（列表 → 设计器）。
5. 登录与记录。

风险：

- 令牌改名会波及 `test/design-tokens.spec.ts` 与 `uno.config.ts`，必须同一提交完成；
- 小程序端不支持 `backdrop-filter`，吸顶栏需提供不透明回退；
- `color-mix()` 在小程序 webview 版本较低时不可用，落地时要换预计算色值；
- 48 → 44 的控制高度会影响现有 e2e 的坐标断言，需要同步调整脚本。

## 10. 已知边界

- 原型是 **file:// 可直接打开的单页应用**，数据为演示数据，不连接真实网关。
- 不覆盖微信小程序真机、公众号 webview 内的真实键盘与安全区差异；这些需落地后真机验证。
- 原型未实现暗色主题、国际化、多租户换肤。
- 登录页的账号密码仅用于演示（admin / 123456），不涉及真实鉴权。
- 设计系统屏（`#/admin/system`）的对比度是运行时用 `getComputedStyle` 读令牌后按 WCAG 公式计算，
  因此永远与 `tokens.css` 同步；文档中的数值是同一套算法的结果。

### 12.4 新增：设计器内嵌手机预览

设计器顶栏的「预览」不再跳转真实作答页，而是就地打开一个手机画框：

- 预览的是**当前草稿**（含未保存的修改），新建问卷、还没保存也能看；
- 覆盖全部 9 种题型：选项行（单选圆 / 多选方）、输入框、日期 / 地址 / 引用入口、图片上传位；
- 只渲染版式，不提交、不校验；关掉改完再打开即最新；
- H5 端 `role="dialog"` + 打开即聚焦 + Tab 循环 + Esc 关闭 + 关闭后焦点回到「预览」按钮；
- 小程序端同一份模板，仅保留点击关闭（无键盘）；
- 底部保留「在新页面打开已保存版本」出口，有未保存修改时仍二次确认；
- 窄屏（<900px）设计器本身隐藏「预览」按钮（顶栏只放保存 / 发布），与既有降级一致。

### 12.5 保留的取舍

- 控制高度收敛为 44（管理端 40），但选项行仍 ≥48；未改动既有 e2e 依赖的类名与结构。
- 产品明确取消「暂存草稿」按钮：草稿本来就是逐题自动保存，手动入口只是重复动作。
- 地址题继续使用 uni 原生 picker，不改成自绘底部弹层（属交互改造）。
- 管理端列表多保留一个显式「搜索」按钮：服务端搜索不能输入即搜（请求竞态 + 乱序）。
