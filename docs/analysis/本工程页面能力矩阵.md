## 2. 关键页面详解（判定最相关）

### 2.1 `editor/stats/index.vue` —— 唯一的运营统计页

**入参**：只有 `activity_no`
```text
// src/pages/editor/stats/index.vue:212-214
onLoad((query) => {
  activityNo.value = readQuery(query, 'activity_no')
})
```
- 全工程**没有任何页面**读 `status` 参数（`grep readQuery(query,'status')` 零命中）。`status` 只被**写进 URL**（`src/domain/questionnaire/routes.ts:72-79` 的 `answerUrl`、`:111-116` 的 `shareAnswerPath`、`src/pages/editor/list/index.vue:189`、`src/pages/editor/design/index.vue:205-210` 的预览入口），而接收方从不消费。
- 页面里的「状态」徽标来自活动行真实列：`src/pages/editor/stats/index.vue:262`（`activityStatus` ← `useSurveyStats.ts:87` ← `srvdaq_init_view_select` 返回的 `status`）。

**取数链路（三层，互不阻塞）**

| 层 | 代码位置 | 说明 |
| --- | --- | --- |
| 配置 | `src/api/daq/stats.ts:216-219` `statsActivityConfig` → `srvdaq_init_view_select`(plain) | 标题、满分、题目/选项定义 |
| 聚合 | `src/api/daq/stats.ts:104-178` `statsAggregates` | 一次 `multi/select` 发 4 个子请求：`state by`+count/avg/max/min、`create_time by_date`、`score by`、`fill_batch_no by`；**每个子请求都显式拼 `activity_no` 条件**（`:110-114`，注释说明 group 不会自动带） |
| 记录 | `src/api/daq/stats.ts:222-231` `statsReplyPage` → `srvdaq_record_reply_select`（**不传 `user_no`**） | 明细表与导出的数据源 |
| 逐题 | `src/api/daq/stats.ts:187-213` `statsBatchQuestionRows` → `srvdaq_record_reply_merge_select` 按 `fill_batch_no` 逐批 `group`，`multi/select` 每 20 批合一次 HTTP | merge 服务**没有 `activity_no` 列**，`in` 条件实测报「系统繁忙」，故只能逐批 |

**8 项能力逐条核对**

**明确的缺失**
- 明细表**行不可点击**（`stats/index.vue:571-583` 无 `@click`/`role="button"`），也没有任何跳转到 `index/result?fill_batch_no=...` 的入口 → 运营看到某行无法打开该答题人的整份答卷。
- 导出不含 `company` / `user_phone`（虽然 `record_reply_select` 的 `*` 能取到，`src/api/daq/types.ts:127-130` 注释亦说明由后端填充），也没有「按部门/分类」维度。
- 未使用平台统计宽表与分类统计服务：`srvdaq_classify_countpc_select`、`srvdaq_record_reply_count_select`、`srvdaq_view_result_all_select`、`srvdaq_record_reply_with_fill_select` 在全工程**零调用**（`docs/平台-问卷表与服务清单.md:96-99` 列出的服务里这些均未接线）。

### 2.2 `questionnaire/index/index.vue` + `QuestionnaireRunner.vue` —— 答题 / 只读预览

**入参**：`activity_no`、`formType`、`fill_batch_no`（`index.vue:48-52`），`status` 未被读取。

**`formType` 的三种只读语义**（`QuestionnaireRunner.vue`）

```text
:109  const isPreview = computed(() => props.formType === 'preview')
:111-116 readOnly = activityEnded || formType==='view' || formType==='detail' || isPreview
:121-126 readOnlyTip  // 预览 / 已结束 / 查看 三种提示文案分开
```

预览为什么是「真只读」——四条独立证据：
1. **不读任何已有作答**：`previewMode` 为真时批次号强制 `undefined`（`:350-353`），可跳过服务端 `user_data` 回填、本地草稿恢复与登记信息预填（`:377-389`）。
2. **固定用 `plain` 取配置**：批次号为空时只走 `plain`（`:364-366`），因此「已结束」的活动也能预览（注释 `:347-349`）。
3. **字段全部禁用**：`:843` `:disabled="readOnly"`。
4. **提交不可达**：整卷模式只读时底部操作栏整块不渲染（`:170-175`）；逐个模式保留翻页但末题只给禁用的「下一题」（`:867-872`，`v-if="!readOnly && lastStep"` 才渲染提交按钮）。

`detail` / `view` 与 `preview` 的差别：前两者**会**按 `fill_batch_no` 回填该批次作答（用于「看一下我上次答的」），`preview` **不会**。已结束活动（服务端 `status === '已结束'`，`:102`）自动只读。

### 2.3 `questionnaire/index/result.vue` —— 单份答卷结果（可看任意人）

```text
// src/composables/useResultPage.ts:55-59
onLoad((query) => {
  activityNo.value = readQuery(query, 'activity_no')
  batchNo.value = readQuery(query, 'fill_batch_no')
  void init()
})
```
- 取数：`initViewSelect({ mode:'use', fillBatchNo })` 拿配置 + `user_data`（`:72-76`，失败退 `plain` `:77-83`）；`recordReplySelect({activityNo, fillBatchNo})` 拿服务端 `score`（`:112-116`）；`recordReplyMergeSelect({fillBatchNo})` 拿逐题值（`:132-135`）。
- **没有归属校验**：不使用 `user_no`、不读 `session`、不与「本机批次」比对。凡知道 `activity_no + fill_batch_no` 的人都能打开该份答卷 —— 与 `RecordList` 的「我的」过滤形成对照（`src/domain/questionnaire/records.ts:1-17` 已把这点记为「体验层门槛，不是安全边界」）。
- **只读**：`autoUpdateState:false`（`:75`、`:81`，避免查看结果时把活动状态改掉），全文件无写接口；页面仅渲染分数、逐题回顾、建议入口。

### 2.4 `history` 系列 —— 只到「我的」

`history/history.vue` 与 `survey/history.vue` 都是 22 行壳页面，正文共用 `RecordHistory` → `RecordList`：
- 请求带 `userNo`（`RecordList.vue:152-158`，`session.userInfo?.user_no || undefined`）。
- 前端再过滤一次：`visibleRows = filterMyRecords(rows, {userNo, myBatches}).mine`（`:70-76`）。
- 归属判定：本机批次优先，其次 `user_no` 相等（`src/domain/questionnaire/records.ts:28-43`）。
- 未登录时 `record_reply_select` 会返回该活动全部记录（`docs/.../服务清单.md:76` 已记录），界面只显示本机批次并提示「已隐藏 N 条其他账号的记录」（`RecordList.vue:127-135`）。

**结论**：它是「填写者视角 / 我的记录」，**不能**当作管理端「该问卷全部答题人记录」使用。

### 2.5 其余页面要点（简）

- `editor/list/index.vue`：无入参启动页；状态筛选值是平台枚举 `未开始/进行中/已结束`（`src/composables/useEditorList.ts:32`），筛选走服务端（`:83`）；行操作 `统计/设计/答题/删除`（`index.vue:179-218`）。
- `editor/design/index.vue`：入参 `activity_no`（`useEditorDesign.ts:172-173`）；保存 / 发布（发布 = 保存 + `status='进行中'`）/ 放弃 / 手机预览；无分析能力。
- `cover/index.vue`：入参 `activity_no`；展示题目数、截止日、`submit_count`（已答人数）、`answer_times`、`perm_type`；入口为「开始作答」（`:210-212`）与「记录」（`:214-216`），二维码内容是本页绝对地址（`:63`）。
- `submitInfo.vue`：入参 `activity_no`；登记信息写本机并随提交写库（`QuestionnaireRunner.vue:575-593`）。
- `survey/result.vue`、`assessmentResult.vue`：入参 `activity_no + fill_batch_no`；只有 `srvdaq_activity_sug_select` 的建议文案，无分数/逐题（`SuggestionPanel.vue:49-60` 校验缺批次时明确提示）。
- `couple.vue`：无入参，按登录 `user_no` 聚合「我完成的测评」，同一问卷取最近一次（`:67-92`）。
- `login/index.vue`：`reason/notice/redirect`，`redirect` 仅接受应用内相对路径（`:32-37`）。

## 3. 对「平台行按钮 → 本工程页面」判定的直接结论

> 前提：平台按钮配置在 `bxsys_buttons_customize`（`docs/平台-问卷表与服务清单.md:42`），其目标 URL 的实参以另一路（woa-analyst / vpages-analyst）的结论为准。此处只回答「本工程对应能力是否等价」。

| 旧按钮典型语义 | 本工程可替代页面 | 是否等价 | 差异与风险（判定要点） |
| --- | --- | --- | --- |
| **统计分析**（传 `activity_no`，可能附带 `status=进行中/已结束`） | `pages/editor/stats/index?activity_no=...` | **主体可比，但有一处语义不确定** | ① 本页**完全不读 `status`**（`stats/index.vue:212-214`）；若旧页用 `status` 切换「进行中看实时数据 / 已结束看归档」，本工程只有**一种**模式（永远按 `activity_no` 全量读现有记录）。② 本页能力更强（服务端聚合 KPI/趋势/分布/逐题 + 两份 CSV）；旧页若有「分类宽表」或「按部门」维度则本页缺失（`classify_countpc_select` 未接线）。③ 明细表不可点开单份答卷。 |
| **查看结果**（`srvdaq_view_result_all_select`，通常带 `activity_no`，可能带用户/批次） | 无等价页面 | **不等价（最大缺口）** | 本工程**没有**「按 `activity_no` 列出全部答卷并逐份打开」的页面：`history` 只到「我的」，`stats` 有全量表格但行不可点，`index/result` 需自带 `fill_batch_no` 才能看单份。三个能力被拆在三处，缺一个组合页。 |
| **答题 / 预览 / 查看**（`activity_no` + `formType` + `fill_batch_no`） | `pages/questionnaire/index/index`（或 `survey/survey`） | **等价** | `formType=preview` 真只读且不读历史作答；`formType=detail/view` 只读并回填指定批次；`status` 参数可安全忽略（本工程从服务端列判定是否已结束）。 |
| **作答记录**（若语义是「该问卷全部答题人」） | `pages/questionnaire/history/history` | **不等价** | 本页强制「我的」（`RecordList.vue:66-76,152-158`）。若旧按钮是管理员查看全部记录，替代后**会少数据**（且未登录时会静默只显示本机批次）。 |
| **评估结果 / 调研结果**（`activity_no + fill_batch_no`） | `assessmentResult` / `survey/result` | **等价** | 同源同服务，仅建议文案；缺批次号有明确提示。 |
| **问卷列表 / 设计器 / 封面 / 登录** | 对应页面均存在 | **等价或增强** | 列表新增服务端搜索与状态筛选；设计器为可视化三栏。 |

**给 Lead 的一句话判定**：本工程在「填写端」与「统计侧主体指标 + 导出」上可替代旧页；**在「问卷维度列出全部答卷并逐份查看」这一整块能力上缺口明确**（`history` 只有我的、`stats` 明细行不可点、`result` 无列表入口），且**所有页面都不消费 `status` 参数**——若旧按钮依赖该参数切换页面形态，需要平台侧改传 `activity_no` 单参，或补一层参数映射。
