# 问卷域 · 平台表与服务清单

> 本文记录问卷（daq 应用）在本工程中实际用到的数据表、服务，以及 2026-11-06 在 parkDev（`http://192.168.0.214/bxapi`）实测到的约束与坑。
>
> **用法**：改任何与问卷数据相关的逻辑前先查这里，避免重新探测一遍；表结构以**平台列定义**为准，本文只记录与本工程相关的部分。
>
> 探测日期：2026-11-06。探测方式：`srvsys_service_columnex_v2_select` 取列元数据 + 真实活动/记录数据回读。

## 三、关键约束与踩坑（实测）

### `act_option` 是「是否计分」的权威字段

- 平台枚举：**`评分` / `不评分`**（不是编辑器里曾写的「评分 / 提交确认」）。
- **历史脏值存在逗号组合** `"评分,提交确认"`（真实活动 `20251108162243000001`，总分 90、及格线 100，确实是计分问卷）。
- 判定必须用**包含匹配**，且**先判「不评分」**（`'不评分'.includes('评分')` 为真）。
- 字段缺失时回退到 `total_points > 0`。

### 选项顺序由客户端负责

- 平台按 **`option_seq`** 排序，**完全无视 `option_view_no`**。实测把 seq 打乱成 A=3/B=1/C=4/D=2 后，`init_view_select` 返回 `B → D → A → C`。
- 权威顺序是 `option_view_no`（A..Z 枚举），前端 `mapper.toFieldOptions()` 已按它稳定排序。
- 平台三张配置表的 `order` 参数**不可用**（传了报「系统繁忙」）。

### `answer_times` 后端不强制

- 枚举 `1次 / 多次`，默认 `1次`。
- **实测同账号同活动连续提交两次都 SUCCESS**，各生成新批次号 → 「每人一次」只能后端加校验，前端只能做入口隐藏。

### `perm_type` 是活动级闸门

- 枚举 `匿名访问 / 登录访问`。
- 活动为「登录访问」时，**匿名提交直接返回 `0011 当前活动接口需要登录访问`**（错误信息说的是「活动」不是「服务」）。

### `company` 由平台自动填充

- 提交时不传 `company`，记录里仍会是登录账号的机构名（如「延安高新区创新科技产业园」）。
- 前端一旦传了 `company`（如登记信息页），会**覆盖**平台自动值。

### 匿名提交的 `user_no`

- 带票据：`user_no` = 登录账号（如 `jq`）。
- 不带票据：每次提交生成新的 32 位随机值。
- 所以「是否已作答」在登录态可靠，匿名态只能靠本机批次号记忆。

### 记录级联

- 删除 `bxdaq_record_reply` 一行，会**级联删除**该 `fill_batch_no` 下五张 storage 明细。

### 分类冗余计数

- `bxdaq_classify.number`（问卷数量）是冗余列，实测「问卷」「健康自我评测」为 1，而「服务调研」「身体健康问卷」为空 —— 未被维护，**不能当权威计数**。

### 不支持的能力（实测，别再试）

| 能力 | 实测结果 | 影响 |
| --- | --- | --- |
| `srvdaq_record_reply_select` 的 `group` 聚合 | `SEARCH_COLUMS_NOT_EXISTS`（`count(*) as cnt` 不被接受为查询列） | 无法按活动批量计数：「回收份数」只能逐条 count，或读 `submit_count`（该列未维护，见下） |
| `srvdaq_record_reply_select` 的 `neq` 条件 | `RULE_TYPE_NOT_EXISTS`（操作符号不合法） | 「已提交 = 非未完成」无法下推服务端，只能本地过滤 |
| `srvdaq_activity_cfg_select` 的 `order` | 传任何排序字段都返回 0 条且不报错（静默失效） | 列表顺序只能依赖服务端默认 |
| `srvdaq_activity_score_sug_select` 匿名调用 | `0011 …无权限访问` | 分数区间说明只能在登录态消费 |
| `srvdaq_activity_sug_select` 未命中规则 | `SUCCESS` + **空数组**（不返回 `no_sug_desc`） | 匿名结果页拿不到「没命中」的兜底文案 |

### `submit_count` 未被维护

- `bxdaq_activity_cfg.submit_count` 是 `trig_act` 计数列，**实测没有生效**：活动 `20261106171651000002` 实际有 2 条作答记录，该列是空的。
- 列表页因此缺省显示「—」而不是「0」，权威数字以统计页（按记录表实时聚合）为准。

## 五、2026-11-06 的改动（与本清单相关）

- 新增只读预览模式：`formType=preview`，只读、不写、不读历史作答。
- 新增二维码（`utils/qrcode.ts` + `BxQrCode.vue`），封面与预览页展示，可点击放大。
- 草稿改为只写本机，`srvdaq_activity_result_save` 不再调用。
- 结果页判据从「分值合计 > 0」改为 `act_option`。
- 选项排序改由前端按 `option_view_no` 负责。
- 文本题一律渲染多行（不再看 `item_type_attr.view_model`）。
